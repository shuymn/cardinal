# Prior art per module

cardinal spends its own design and code on its core domain: arbitrating compute and disk for parallel coding agents, tied to the agent lifecycle. Everything else reuses prior work, in this order: adopt an implementation (a crate, a tool, an OS facility); else adapt an established design under its own name, terms, and defaults. Whatever the decision, an implementation of cardinal's own included, its tests borrow the checks of projects that solved the same problem (conformance suites, test vectors, test cases), so verification does not start from zero.

This document records that comparison for every module of the [module table](architecture.md#22-modules) and every piece of the test harness, each module as phase 1 builds it; `act`'s execution (unit X, [architecture §9.7](architecture.md#97-executing-regenerable-directories)) is marked planned. Crate decisions are in [architecture §12](architecture.md#12-libraries) and system-level prior art in [design §13](design.md#13-prior-art); rows link to them instead of repeating them. `crates/cardinal/tests/prior_art.rs` reads this file as GitHub Flavored Markdown and fails when a module that `tests/layering.rs` knows has no row, when a row names a module or harness path that does not exist, when a row lacks its kind or decision, and when a borrowed-checks cell is neither an existing test nor an exception as defined below.

## Columns

- **Kind**: `core` when the module exists for cardinal's domain and no other project solves the same problem; `generic` when other kinds of projects solve its mechanisms (logs, failpoints, process supervision, shell tokenizing, git output, alert lifecycles).
- **Decision**: `adopt` (use the implementation), `adapt` (an implementation of cardinal's own of the named design, with its terms), or `own` (a design of cardinal's own), each followed by its reason.
- **Borrowed checks**: the repository path of the test file or suite directory that runs another project's suite, vectors, or cases against cardinal's code. A row without one is an exception and says so: `not ported:` names a suite that exists and is not used yet, `none found:` names what was searched, and both link upstream and give the reason. Test code and data are copied only from permissive licenses (MIT, Apache-2.0, BSD, public domain), with the upstream notice in the file; cases from copyleft projects (git, util-linux's GPL parts, logrotate) are derived from their documented behaviour without copying text.
